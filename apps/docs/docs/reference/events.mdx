emailkit turns provider events into the same set of hooks. This page lists the data each hook receives.

## Email hooks

Configure hooks under `hooks.email`:

| Hook           | Event                                                                              |
| -------------- | ---------------------------------------------------------------------------------- |
| `onInbound`    | A received message with addresses, bodies, reply context, headers, and attachments |
| `onOutbound`   | A sent-email event in emailkit's shared format                                     |
| `onDelivered`  | Delivery confirmation and optional response time                                   |
| `onOpened`     | Open details, client data, location, and bot detection when available              |
| `onClicked`    | Link URL, client data, location, and bot detection when available                  |
| `onBounced`    | Reason, severity, SMTP response, and error code when available                     |
| `onComplained` | Feedback details when available                                                    |
| `onRejected`   | Provider rejection reason and category                                             |
| `onUnknown`    | A verified provider event emailkit cannot normalize                                |
| `onAll`        | Every email event plus the `emailDriver` that produced it                          |

## Resource hooks

Resource hooks are also the write side of emailkit's stateless design. Connect them to your database when your app needs to remember mailbox, domain, or webhook changes.

| Group     | Hooks                                                                                |
| --------- | ------------------------------------------------------------------------------------ |
| `mailbox` | `onConnected`, `onCreated`, `onDeleted`, `onAuthUpdated`                             |
| `domain`  | `onCreated`, `onVerified`, `onDeleted`                                               |
| `webhook` | `onCreated`, `onUpdated`, `onDeleted`, `onActionRequired`, `onSyncRequired`, `onAll` |

These events include the provider ID, action, affected item, reason, suggested next step, time, and any original provider data.

## Important behavior

- Live webhooks and recovered events both use the same hooks.
- The same event can arrive more than once, so hooks should safely ignore duplicates.
- emailkit verifies provider webhooks before running your hooks.
- A field stays optional when the provider does not supply it; emailkit does not invent a value.
- The original event stays available in `raw` for debugging and provider-specific work.

:::note
Build your app around emailkit's shared fields. Use `raw` only in the small areas that need provider-specific data.
:::
